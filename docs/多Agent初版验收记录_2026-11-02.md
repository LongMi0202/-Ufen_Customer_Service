## 同提交自动冒烟对照

固定用例版本：`welfare-agent-eval-v1`。10个用例每种模式运行一次，共20次。所有自动检查通过，内容包括回复类型、必要工具、积分字段引用、政策来源、页面动作、领域覆盖、无未完成任务、无意外业务写入和业务快照一致性。

本轮平均执行耗时：single 7.19秒，multi 11.25秒；总 Token：single 196,200，multi 257,972。多 Agent 在这组样本中整体更慢且消耗更多 Token；价值主要在显式任务编排、领域边界和审计，当前结果不支持宣称性能或成本提升。转人工样例的 multi 跳过模型，因此该样例 Token 为0；它不代表人工客服接入只需0.04秒。

只有每例一次，且存在供应商缓存、网络与模型输出波动，不能据此给出稳定的P95、吞吐或生产费用结论。两种模式的供应商重试配置和输出长度差异已在原始记录的 `model_configuration` 保留。Token 未换算货币费用。

## 抽查发现及局部复测

自动检查之外的回复抽查发现过一条临期日期被重复加8小时的表达。已强化“带+08:00即北京时间”的指引，并用业务批次原日期时刻作为对照局部复测。单／多模式重新回答均显示正确的 `2026-11-20 22:20:38（北京时间）`，日期对照通过。

同时限制多 Agent 中订单工具的模型视图：订单、物流、售后、主控及上游上下文不再从订单附带的 refund 字段扩展未分派的退分结论；退分查询使用专用工具。原始工具结果仍完整保存供审计，业务 API 未变。复测的售后规则回答正确区分售后处理中、规则条款和未查询的退分状态。

局部复测记录：[2026-11-02-post-review.json](evaluation/2026-11-02-post-review.json)。它与上表的固定提交记录分开保存，保留此次修正过程。

模型偶发误路由、结构化结果不稳定及自然语言语义偏差，仍需要更大且独立的用例集持续评估。当前字段／政策／动作校验和有限纠错不能证明所有自然语言结论正确。此次结果不作为简历中85%复合成功率或75%自动解决率的证明。

## 复现与查看

```powershell
docker compose up -d
python -X utf8 tests/benchmark_agents.py --suite review --modes single multi
python -X utf8 tests/benchmark_agents.py --suite all --modes single multi --output tmp/agent-evaluation/recheck.json
```

评测使用只读查询，诊断 Run 有独立编号。API业务回归会创建并取消测试订单，保留审计，不重置现有数据卷。环境使用实际 `.env` 中本地配置，密钥未纳入版本。

员工端：<http://127.0.0.1:5173/chat>；管理／客服端：<http://127.0.0.1:5174>。模式切换与详细参数见[实现与运行说明](多Agent实现与运行验收.md)。
